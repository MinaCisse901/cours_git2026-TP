Qu'est-ce qu'un tag Git ?

Un pointeur fixe vers un commit spécifique

  • Marque des versions importantes (releases)
  • Ne change jamais (contrairement aux branches)
  • Utilisé pour v1.0.0, v2.1.3, etc.

Pourquoi utiliser des tags ?

  • Identifier facilement les versions publiées
  • Revenir à une version spécifique rapidement
  • Documenter l'historique des releases
  • Faciliter le déploiement et la distribution

Types de tags

  • Lightweight : Simple pointeur vers un commit
  • Annotated : Objet Git complet avec métadonnées (auteur, date, message)

💡 Privilégier les tags annotés pour les releases

Créer un tag lightweight

Tag simple sans métadonnées :

git tag v1.0.0

Crée un tag sur le commit actuel (HEAD)

Créer un tag annotated

Tag avec message et métadonnées :

git tag -a v1.0.0 -m "Première version stable"

✅ Recommandé pour marquer les releases officielles

Lister et afficher les tags

Lister tous les tags :

git tag

Voir les détails d'un tag :

git show v1.0.0

Pousser les tags vers le dépôt distant

Pousser un tag spécifique :

git push origin v1.0.0

Pousser tous les tags :

git push origin --tags

Versionning sémantique (semver)

MAJOR.MINOR.PATCH

Exemple : v2.3.1

Structure du versionning sémantique

  • MAJOR (2) : Changements incompatibles (breaking changes)
  • MINOR (3) : Nouvelles fonctionnalités compatibles
  • PATCH (1) : Corrections de bugs

Exemples d'évolution de versions

  • v1.0.0 → v1.0.1 : Correction d'un bug
  • v1.0.1 → v1.1.0 : Nouvelle fonctionnalité
  • v1.1.0 → v2.0.0 : Changement majeur incompatible

Revenir à une version taguée

Examiner le code à une version spécifique :

git checkout v1.0.0

⚠️ Mode "detached HEAD" : pour lecture uniquement

Git dans VS Code

VS Code intègre Git nativement :

  • Panneau Source Control (icône branche)
  • Visualisation graphique des changements
  • Interface pour staging, commit, push, pull

Fonctionnalités Git dans VS Code

  • Diff visuel ligne par ligne
  • Staging de fichiers par clic
  • Historique des commits (avec extension)
  • Gestion des branches et merge

Extension GitLens

Extension populaire pour améliorer Git dans VS Code :

  • Historique détaillé par fichier et ligne
  • Annotations git blame inline
  • Comparaison de branches visuellement

Bonnes pratiques : Tags et versions

  • Utiliser semver (MAJOR.MINOR.PATCH)
  • Toujours créer des tags annotés avec -a
  • Rédiger un changelog pour chaque release
  • Ne jamais modifier ou supprimer un tag publié

Récapitulatif

  • Tags = pointeurs fixes pour marquer versions
  • Semver = convention standard (MAJOR.MINOR.PATCH)
  • VS Code intègre Git avec interface graphique
  • GitLens enrichit l'expérience Git dans l'IDE
