Séance 2 – Suivi de versions et gestion des modifications

  • Maîtriser les commandes de comparaison et d'inspection

Rappel : Séance 1

  • Le versionning résout le chaos des versions multiples
  • Git = système distribué puissant
  • Commandes de base : init, add, commit, status, log
  • Chaque commit = instantané du projet

Les trois zones de Git

  • Working Directory : Dossier de travail (vos fichiers)
  • Staging Area (Index) : Zone de préparation avant commit
  • Repository (.git) : Historique des commits

Flux de travail

Working Directory → git add → Staging Area

Staging Area → git commit → Repository

Cycle de vie des fichiers (détaillé)

  • Untracked : Nouveau fichier, Git ne le suit pas encore
  • Unmodified : Fichier commité, aucune modification
  • Modified : Fichier modifié depuis dernier commit
  • Staged : Modification prête à être commitée

git status – Inspecter l'état

Affiche l'état actuel de votre dépôt :

  • Branche courante
  • Fichiers modifiés non stagés
  • Fichiers stagés prêts à commiter
  • Fichiers untracked

git diff – Comparer les changements

  • git diff : Changements non stagés
  • git diff --staged : Changements stagés
  • git diff HEAD : Tous les changements depuis dernier commit

git add – Options utiles

  • git add fichier.txt : Ajouter un fichier spécifique
  • git add . : Ajouter tous les fichiers du dossier courant
  • git add -A : Ajouter tous les fichiers (y compris suppressions)

git log – Options avancées

  • git log --oneline : Historique compact (1 ligne/commit)
  • git log -n 5 : Afficher les 5 derniers commits
  • git log --graph : Visualisation graphique

Corriger le dernier commit

Vous avez oublié un fichier ou fait une erreur dans le message ?

git commit --amend

⚠️ Modifie le dernier commit (ne pas utiliser si déjà poussé)

Annuler des modifications

  • git restore fichier.txt : Annuler les modifs non stagées
  • git restore --staged fichier.txt : Retirer du staging
  • git checkout -- fichier.txt : (ancienne syntaxe)

Annuler un commit (revert)

Créer un nouveau commit qui annule les changements d'un commit précédent :

git revert <commit-hash>

✅ Sûr : conserve l'historique

git reset (usage avancé)

  • git reset --soft HEAD~1 : Annuler commit, garder staging
  • git reset --mixed HEAD~1 : Annuler commit et staging
  • git reset --hard HEAD~1 : Annuler tout (⚠️ dangereux)

Scénario 1 : Fichier oublié

J'ai fait un commit mais j'ai oublié un fichier !

git add fichier_oublie.txt

git commit --amend --no-edit

Scénario 2 : Mauvais message de commit

Mon message de commit contient une faute ou n'est pas clair :

git commit --amend -m "Nouveau message"

Scénario 3 : J'ai cassé le code

Je veux abandonner toutes mes modifications locales :

git restore .

⚠️ Changements non stagés perdus définitivement

TP Guidé (60 min)

  1. Modifier plusieurs fichiers, utiliser git diff
  2. Ajouter sélectivement au staging, faire des commits
  3. Corriger un commit avec --amend
  4. Créer un commit à annuler avec revert

Bonnes pratiques

  • Faire des commits fréquents et petits
  • Toujours vérifier avec git status avant commit
  • Utiliser git diff pour réviser les changements
  • Écrire des messages de commit clairs et descriptifs

Récapitulatif

  • Git utilise trois zones : working, staging, repository
  • diff, status, log permettent d'inspecter l'état
  • amend, restore, revert corrigent les erreurs
  • reset est puissant mais à utiliser avec précaution
