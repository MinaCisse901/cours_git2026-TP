Versionning avec Git

Séance 1 – Introduction au Contrôle de Versions

Objectifs de la séance

  • Comprendre les problèmes du développement sans versionning
  • Définir les concepts clés : dépôt, commit, historique
  • Installer et configurer Git sur votre machine

Le problème sans versionning

Comment gérez-vous vos projets actuellement ?

  • projet_v1.zip
  • projet_v1_final.zip
  • projet_v1_final_definitif.zip
  • projet_v1_final_definitif_vraiment.zip 😰

Conséquences du chaos

  • Perte de l'historique des modifications
  • Impossible de revenir à une version antérieure
  • Collaboration difficile en équipe
  • Risque de conflits et de perte de code

La solution : Le contrôle de versions

Un système qui enregistre les changements d'un fichier ou ensemble de fichiers au fil du temps pour rappeler des versions spécifiques ultérieurement.

Concepts de base

  • Dépôt (Repository) : Espace de stockage du projet et son historique
  • Commit (Version) : Instantané des modifications à un moment donné
  • Historique : Chaîne chronologique de tous les commits

Types de systèmes de versionning

  • Centralisés : Un serveur central (ex. SVN, CVS)
  • Distribués : Chaque développeur a une copie complète (ex. Git, Mercurial)

Pourquoi Git ?

  • Créé par Linus Torvalds en 2005
  • Système distribué : travail déconnecté possible
  • Rapidité et performance
  • Branches légères et fusion flexible
  • Utilisé massivement (GitHub, GitLab, Bitbucket)

Git vs Plateformes distantes

  • Git : Outil en ligne de commande (local)
  • GitHub / GitLab / Bitbucket : Services web pour héberger et partager des dépôts Git

Git = moteur • GitHub = plateforme collaborative

Installation de Git

Vérifier si Git est déjà installé :

git --version

Si non installé : télécharger depuis git-scm.com

Configuration initiale

Configurer votre identité (obligatoire) :

git config --global user.name "Votre Nom"

git config --global user.email "email@exemple.com"

Vérifier la configuration :

git config -l

Créer votre premier dépôt

  1. Créer un dossier pour votre projet
  2. Naviguer dans ce dossier en ligne de commande
  3. Initialiser le dépôt :

git init

→ Crée un dossier caché .git contenant l'historique

Cycle de vie des fichiers

  • Untracked : Fichier non suivi par Git
  • Staged : Fichier prêt à être commité
  • Committed : Fichier enregistré dans l'historique

Commandes essentielles

  • git status : Afficher l'état actuel du dépôt
  • git add fichier.txt : Ajouter un fichier au staging
  • git commit -m "message" : Créer un commit
  • git log : Afficher l'historique des commits

Réaliser votre premier commit

  1. Créer un fichier : README.txt
  2. Vérifier l'état : git status
  3. Ajouter au staging : git add README.txt
  4. Commiter : git commit -m "Initial commit"

TP Guidé (45 min)

  1. Créer un dossier mon-projet-git
  2. Initialiser un dépôt Git
  3. Créer 3 fichiers (README.txt, todo.txt, script.py)
  4. Réaliser 3 commits distincts

💡 Vérifiez votre historique avec git log

Bonnes pratiques : Messages de commit

  • ✅ Clair et concis (impératif) : "Ajouter README"
  • ✅ Décrire ce qui a changé et pourquoi
  • ❌ Messages vagues : "update", "fix", "test"

Récapitulatif

  • Le versionning résout le chaos des fichiers multiples
  • Git est un système distribué puissant
  • git init, add, commit, status, log sont vos premiers outils
  • Chaque commit capture un instantané du projet
