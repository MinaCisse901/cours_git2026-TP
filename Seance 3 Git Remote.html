  • Collaborer avec d'autres développeurs

  • Accéder au code depuis n'importe où

Architecture distribuée

Dépôt local (votre ordinateur)

⬆️ push / pull ⬇️

Dépôt distant (GitHub/GitLab/Bitbucket)

Qu'est-ce qu'un remote ?

Un remote est une référence à un dépôt distant

  • Nom conventionnel : origin
  • URL du dépôt distant (HTTPS ou SSH)
  • Permet de synchroniser local ↔ distant

Plateformes d'hébergement Git

  • GitHub : La plus populaire (Microsoft)
  • GitLab : Open source, CI/CD intégré
  • Bitbucket : Intégration Atlassian (Jira)

Nous utiliserons GitHub/GitLab dans ce cours

Créer un compte (GitHub/GitLab)

  1. Aller sur github.com ou gitlab.com
  2. S'inscrire avec email (gratuit)
  3. Vérifier l'email de confirmation
  4. Configurer le profil (nom, photo, bio)

Créer un nouveau dépôt

  1. Cliquer sur "New repository" (GitHub) ou "New project" (GitLab)
  2. Nommer le dépôt (ex. mon-projet-git)
  3. Choisir Public ou Private
  4. Ne pas initialiser avec README (on a déjà un projet local)

Lier un dépôt local à un dépôt distant

Ajouter le remote origin :

git remote add origin https://github.com/user/repo.git

Vérifier :

git remote -v

Envoyer des commits (push)

Pousser vos commits vers le dépôt distant :

git push -u origin main

-u : configure le suivi de la branche distante

Cloner un dépôt distant

Télécharger un dépôt existant :

git clone https://github.com/user/repo.git

Crée un dossier avec le nom du dépôt, configure automatiquement origin

Récupérer les changements (fetch)

Télécharger les nouveaux commits sans les fusionner :

git fetch origin

✅ Sécurisé : permet d'inspecter avant fusion

Récupérer et fusionner (pull)

Télécharger et fusionner automatiquement :

git pull origin main

pull = fetch + merge

Différence fetch vs pull

  • fetch : Télécharge sans fusionner (sécurisé)
  • pull : Télécharge et fusionne automatiquement

💡 Bonne pratique : fetch d'abord, inspecter, puis merge

Workflow collaboratif

  1. Faire vos modifications localement
  2. Commiter vos changements
  3. Fetch/Pull pour récupérer changements des autres
  4. Résoudre conflits éventuels
  5. Push vers le dépôt distant

Fichiers importants

  • README.md : Documentation du projet (Markdown)
  • .gitignore : Fichiers à ne pas versionner

Ex. .gitignore : node_modules/, *.log, .env

TP Guidé (60 min)

  1. Créer un compte GitHub/GitLab
  2. Créer un nouveau dépôt distant
  3. Publier votre projet local (remote add, push)
  4. Cloner le dépôt du professeur, modifier, push

Bonnes pratiques

  • Toujours pull avant de commencer à travailler
  • Commiter et push régulièrement
  • Écrire un README.md clair et complet
  • Utiliser .gitignore pour exclure fichiers inutiles

Récapitulatif

  • Remote = référence à un dépôt distant (origin)
  • clone : télécharger un dépôt existant
  • push : envoyer vos commits
  • fetch/pull : récupérer les changements des autres
