Qu'est-ce qu'une branche ?

Une branche est un pointeur mobile vers un commit

  • Permet de développer des fonctionnalités isolément
  • Protège la branche principale (main/master)
  • Facilite la collaboration en équipe

Pourquoi utiliser des branches ?

  • Développer une nouvelle fonctionnalité sans casser le code principal
  • Corriger un bug en isolation
  • Expérimenter sans risque
  • Travailler en parallèle sur plusieurs tâches

La branche principale (main/master)

Par défaut, Git crée une branche appelée main (ou master)

  • Contient le code stable et testé
  • Point de départ pour créer de nouvelles branches
  • Ne devrait jamais contenir de code cassé

Créer une nouvelle branche

Créer une branche appelée "feature" :

git branch feature

⚠️ Crée la branche mais ne bascule pas dessus

Basculer vers une branche

Commandes pour changer de branche :

git checkout feature

Ou (syntaxe moderne) :

git switch feature

Créer et basculer en une seule commande

Raccourci pratique :

git checkout -b feature

Ou (syntaxe moderne) :

git switch -c feature

Lister les branches

Voir toutes les branches locales :

git branch

Voir toutes les branches (locales + distantes) :

git branch -a

Fusionner des branches (merge)

Pour intégrer les changements d'une branche dans une autre :

  1. Basculer vers la branche cible (ex. main)
  2. Fusionner la branche feature : git merge feature

Types de fusion

  • Fast-forward : Déplacement simple du pointeur (pas de divergence)
  • Merge commit : Création d'un commit de fusion (historiques divergents)

Qu'est-ce qu'un conflit ?

Un conflit survient quand deux branches modifient la même ligne d'un fichier

Git ne peut pas décider automatiquement quelle version garder → intervention manuelle nécessaire

Identifier un conflit

Lors du merge, Git affiche :

CONFLICT (content): Merge conflict in fichier.txt

Vérifier l'état :

git status

Marqueurs de conflit dans le fichier

<<<<<<< HEAD

Votre version (branche courante)

=======

Version de la branche à fusionner

>>>>>>> feature

Résoudre un conflit (étapes)

  1. Ouvrir le fichier en conflit dans un éditeur
  2. Choisir quelle version garder (ou combiner)
  3. Supprimer les marqueurs de conflit
  4. Sauvegarder le fichier

Finaliser la résolution

Après avoir résolu manuellement :

git add fichier.txt

git commit

Git génère automatiquement un message de commit de fusion

Supprimer une branche

Après fusion, supprimer la branche feature :

git branch -d feature

-d : suppression sécurisée (refuse si non fusionnée)

-D : suppression forcée

TP Guidé (60 min)

  1. Créer une branche feature, faire des commits
  2. Basculer sur main, fusionner feature (fast-forward)
  3. Créer deux branches avec modifications conflictuelles
  4. Résoudre manuellement un conflit de fusion

Workflow "Feature Branch"

  1. Créer une branche pour chaque fonctionnalité
  2. Développer et commiter sur cette branche
  3. Tester la fonctionnalité
  4. Fusionner dans main quand c'est prêt
  5. Supprimer la branche feature

Bonnes pratiques

  • Créer des branches avec des noms descriptifs (feature/login, bugfix/typo)
  • Garder les branches courtes (fusionner rapidement)
  • Toujours tester avant de fusionner dans main
  • Supprimer les branches après fusion

Récapitulatif

  • Branches = développement isolé et parallèle
  • branch, checkout/switch, merge : commandes essentielles
  • Conflits : modifications concurrentes nécessitent résolution manuelle
  • Feature branch workflow = pratique standard
